# Rustyfin Installer/Platform/Runtime Open Work Audit

Date: 2026-03-26  
Scope audited: `docs/plans/2026-03-14-linux-bootstrap-installer-design.md`, `README.md`, `AGENTS.md`, `crates/installer`, `scripts/install_linux.sh`, `scripts/rustfin-installer.sh`, `scripts/start-native.sh`, deploy/systemd wrappers, and `docs/operations/debian-12-native-runtime.md`.

This report lists only still-open work. It intentionally excludes already-landed Debian 12/13 installer/runtime behavior.

## Productized Installer Goals Still Open (Beyond Current Debian 12/13 Delivery)

| Problem name | Why it is open | Key files/modules | Recommended implementation approach | Dependencies | What done looks like |
| --- | --- | --- | --- | --- | --- |
| Cross-distro installer adapters and package maps | Full install is hard-gated to Debian 12/13 and prereq install is `apt`-only. | `crates/installer/src/main.rs` (`ensure_current_support_boundary`, `install_debian_prerequisites`), `scripts/install_linux.sh` | Add distro-family adapters (`debian/ubuntu`, `fedora/rhel`, `arch`, `opensuse`) with package maps and repo-enablement hooks; keep boundary checks adapter-driven, not hardcoded. | Distro package matrix + CI lanes for each supported family. | `install_linux.sh` + `rustfin-installer install` succeed on declared Tier-1/Tier-2 distros with explicit unsupported-host failures elsewhere. |
| Linux host policy adapters (SELinux/firewall/sudo/repo policy) | No installer phase currently handles non-Debian host-policy differences. | `crates/installer/src/main.rs` (no policy stage), design doc sections 5.5/9.4 | Add policy stage in installer pipeline for SELinux/AppArmor/firewall/repo semantics with distro-specific implementations and explicit no-op reporting where safe. | Cross-distro adapter layer and host-policy test fixtures. | Installer emits deterministic policy actions/results per distro instead of silent assumptions. |
| Artifact acquisition, version pinning, and rollback | Install/deploy assume an existing git checkout and `git pull --ff-only`; no artifact/channel/rollback model. | `crates/installer/src/main.rs` (`repo_root`, `deploy_native`), `scripts/rustfin-installer.sh` | Add acquisition modes (`git`, `release artifact`), persisted installed-version metadata, channel selection, and rollback command path. | Release artifact publishing pipeline and signed metadata strategy. | Fresh hosts can install from artifact without pre-cloned repo; upgrades are version-pinned and rollback-capable. |
| Shipped installer binary mode | Public wrapper always runs `cargo run`; source + Rust toolchain are mandatory at runtime install time. | `scripts/rustfin-installer.sh`, `scripts/install_linux.sh`, design doc section 6.1 | Ship `rustfin-installer` binary as first-class artifact; bootstrap script prefers binary and falls back to cargo only for development mode. | Release packaging and binary distribution path. | Operators can install/deploy with `/opt/rustyfin/bin/rustfin-installer` without requiring local Rust toolchain. |
| GPU vendor-aware provisioning/inventory by distro | GPU defaults are inferred from tool presence only; no vendor/package provisioning flow or multi-GPU manifest data. | `crates/installer/src/main.rs` (`detect_default_ai_backend`, `resolve_ai_gpu_backend`, `InstallManifest`) | Add GPU module for inventory (`lspci`, device nodes, runtime probes), optional guarded driver/runtime provisioning per distro/vendor, and manifest persistence of selected GPU policies. | Distro adapters + hardware validation matrix (NVIDIA/AMD/Intel, single/multi-GPU). | Installer records GPU inventory/selection in manifest and applies consistent AI/transcription/transcode defaults with explicit driver-state outcomes. |

## Debian 12/13 Remaining Work (Within Current Supported Scope)

| Problem name | Why it is open | Key files/modules | Recommended implementation approach | Dependencies | What done looks like |
| --- | --- | --- | --- | --- | --- |
| Runtime/install layout still repo-coupled | Runtime dirs, logs, pid files, env snapshot, unit working dirs, and service exec paths are still tied to repo-relative paths. | `crates/installer/src/main.rs` (`write_native_runtime_defaults`, `resolve_runtime_paths`, `render_*_unit`), `docs/operations/debian-12-native-runtime.md` | Move runtime state to canonical roots (`/var/lib`, `/var/log`, `/var/cache`), install executable artifacts under `/opt/rustyfin`, and render units against installed paths rather than repo scripts. | Migration plan for existing hosts and ownership transition logic. | Runtime survives repo relocation/removal; services start from installed paths only. |
| Dedicated `rustyfin` service account model | Main runtime user is derived from invoking user context; no dedicated system account lifecycle exists. | `crates/installer/src/main.rs` (`detect_native_user_context`, `render_main_runtime_unit`) | Introduce installer-managed `rustyfin` system user/group creation, ownership assignment for runtime dirs, and fixed service identity in unit rendering. | Runtime layout migration and servers-agent permission alignment. | Services consistently run as `rustyfin` (except explicitly root-only units) across all Debian installs. |
| Persisted config/secrets model is still split | `/etc/rustyfin` defaults exist, but runtime snapshot remains repo-local (`.rustyfin.runtime.env`) and remains a live config source. | `crates/installer/src/main.rs` (`RUNTIME_DEFAULTS_FILE`, `ENV_FILE`, `write_runtime_snapshot_to_path`, `resolve_runtime_paths`), `scripts/start-native.sh` | Define one authoritative persisted runtime config file under `/etc/rustyfin` (root-owned), demote repo snapshot to optional debug export, and update launch/deploy paths to consume canonical config only. | Service unit/env rendering changes and migration of existing values. | Runtime boots from canonical `/etc/rustyfin` config without requiring repo-local env artifacts. |
| Install reporting output is incomplete | Design target includes human-readable install summary file; current installer writes JSON manifest only. | `crates/installer/src/main.rs` (`write_install_manifest`), design doc section 7/13 | Add install summary writer (for operators) and expand manifest fields for actionable runtime/install decisions. | Config/layout unification for authoritative values. | Installer leaves both machine-readable manifest and operator-readable summary with consistent paths/decisions. |
| Preflight checks are not comprehensive | No explicit install preflight currently verifies disk, network reachability, and systemd readiness before mutating host state. | `crates/installer/src/main.rs` (`install`, `detect_host_platform`) | Add preflight stage and fail fast before package/install changes with precise remediation guidance. | None beyond current host-detection scaffolding. | Installer exits early on insufficient prerequisites with clear actionable messages. |
| Bootstrap support messaging mismatch | `install_linux.sh` bootstraps `dnf`/`pacman`/`zypper`, but installer then hard-fails non-Debian full install. | `scripts/install_linux.sh`, `crates/installer/src/main.rs` (`ensure_current_support_boundary`) | Until adapters land, enforce Debian-12/13 support boundary at bootstrap entry and message it before package operations on unsupported hosts. | Product decision: strict Debian-only bootstrap now vs staged multi-distro rollout. | Unsupported hosts fail immediately with unambiguous support-boundary messaging and no misleading partial bootstrap. |
| Remaining shell duplication/drift seam | `install_native_debian.sh` still duplicates prerequisite policy that now exists in Rust installer; `start-native.sh` still owns substantial orchestration shell logic. | `scripts/install_native_debian.sh`, `scripts/start-native.sh`, `crates/installer/src/main.rs` | Convert `install_native_debian.sh` to a thin installer subcommand wrapper (or retire it), and continue pulling remaining runtime orchestration policy into Rust while keeping shell as compatibility glue only. | Additional installer subcommands + docs update. | Single source of truth for install policy; thin wrappers with minimal drift risk. |
| Installer regression/idempotency coverage is thin | Installer crate has only two narrow unit tests and no dedicated automated install/reinstall matrix coverage. | `crates/installer/src/main.rs` tests, `scripts/ci/debian_native_gates.sh` | Add installer integration gates for fresh install, rerun idempotence, deploy cycle, and clean-reset flows on Debian 12/13 test hosts. | CI automation for ephemeral Debian hosts/VMs. | Installer regressions are caught in CI and acceptance criteria are continuously enforced. |
